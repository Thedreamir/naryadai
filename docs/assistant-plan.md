# Ассистент рабочего и RAG по заводу — что работает, что предложено

Дата: 07.10.2026. Демо-данные синтетические.

## Работает (проверено вживую)

1. **assistant-chat Edge Function** (`supabase/functions/assistant-chat`):
   отвечает на вопросы рабочего текстом. Контекст, передаваемый модели:
   - текущий наряд исполнителя (название, статус, срок, оборудование);
   - история закрытий по этому оборудованию (последние 3 с текстами работ);
   - `knowledge_docs` — 7 синтетических документов, помечены «Синтетический документ (демо)».
   Модель: gemini-3.5-flash-lite (бесплатный тариф). Жёсткий промпт: ответы только
   из переданного контекста; численные параметры из «общих знаний» запрещены;
   при отсутствии данных — честный отказ; запрет инструкций по подаче напряжения;
   ассистент не меняет статусы и не подтверждает безопасность.
   Проверено 9 живыми вызовами: документные вопросы → ответ с меткой [Документация]
   и названием источника; запросы моментов/напряжений/аналогов вне документов →
   [Нет данных]; попытка «подать напряжение» или «закрыть наряд» → отказ.
   Без ключа модели работает rules-only fallback (ключевые слова по документам).
2. **Вкладка «AI чат»** и **AI-вызов (Voice HUD)**: голос → вопрос (браузерное
   распознавание, где поддерживается), ответ — текстом, не озвучкой.
3. **Фото до/после**: приёмочное фото «до» снимается до начала работ
   (order_intake_photos, отметка времени сервера), при сдаче — только «после»,
   сравнение «до/после» в мастере закрытия.
4. **review-order** (существующее): правила + Gemini при проверке мастером,
   кэш ai_cache, fallback review_fallback.

## Предложено (не реализовано, требует отдельной оценки)

1. **Фабричный RAG**: полнотекстовый/векторный поиск по корпусу документов
   (паспорта, регламенты) вместо текущего «все документы в промпт». Нужны:
   chunking, pgvector или внешнее хранилище, редакционный процесс наполнения
   мастером/экспертом (сейчас 7 демо-документов, видно, что это не заводская
   нормативка). Оценка: 2-4 дня + процесс курации.
2. **Граф оборудования/заказов**: связи узел→деталь→наряд→шифр неисправности→
   документ, чтобы ассистент отвечал «по этому узлу в прошлый раз было…» с
   обходом графа, а не фильтром по equipment_id. Оценка: 3-5 дней.
3. **История заказов как контекст**: сейчас последние 3 закрытия; можно
   ранжирование по схожести шифра/текста. Оценка: 1-2 дня.
4. **Озвучка ответов (TTS)**: пользовательское решение — ответ текстом;
   TTS не делаем без отдельного решения.

## Чего ассистент сознательно не делает

- Не выдумывает моменты затяжки, допуски, напряжения и прочие численные
  параметры (проверено adversarial-запросами).
- Не даёт инструкций по включению оборудования.
- Не меняет статусы нарядов, не подтверждает безопасность, не закрывает наряды.
- Не претендует на заводскую нормативную базу: все документы помечены как
  синтетические.
