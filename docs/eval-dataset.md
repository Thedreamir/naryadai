# Eval-датасет для проверки ИИ (ground truth) — синтетический

37 помеченных кейсов (scripts/eval-dataset.json), собраны как «организатор хакатона + заводской эксперт». Каждый кейс гоняется через реальный путь: выдача -> допуск -> принятие -> начало -> сдача -> проверка review-order (edge), фикстуры потом закрываются/отменяются. Все тексты синтетические.

## Классы меток
- `good` (15): реалистичные закрытия по типам узлов (лента конвейера, сальник насоса, подшипник дробилки, редуктор, грохот, клапан, элеватор, компрессор, футеровка, датчик, сварка, кабель) — должны дойти до проверки БЕЗ флагов правил. Включён кейс с казахско-русским смешанным текстом (реальный заводской язык).
- `bad` (18): ловушки жюри — расплывчатые тексты («Всё сделал как надо», «Жөндедім, бары жақсы»), текст работ = тексту проблемы (3 шт), цифры/символы вместо описания (2), аномальные количества материалов (0, -2, 999, 500, 100). Должны быть пойманы правилами review ИЛИ заблокированы на записи.
- `guard` (4): должны умереть на границе записи: works<12, нет шифра, внеплановый без фото, несуществующий шифр (ХХ-99).

## Честные ограничения
- Проверяется детерминированный слой правил + граница записи. Живая модель — добавка сверху, её вердикт не меняет метку (Ptah советует, мастер решает).
- Фото-ловушки (старая/чужая фотография) не в этом наборе: детекция дублей работает на клиенте при загрузке, в RPC-путь харнесса не входит. Отдельная проверка.
- Метрики считаются на этом наборе; это не промышленная точность.

## Метрика
Accuracy = (плохие пойманные хоть где-то + хорошие чистые + guard заблокированные) / все. Baseline approve-all = доля good.
